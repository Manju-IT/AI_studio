# Phase 11.3 — local background queue

Apply over Phase 11.2 with all services stopped. No schema migration or new package. Set PYTHONPATH to backend plus project root in both backend and worker terminals. Set QWEN_HF_MODEL_PATH in the **worker** terminal if needed. Start backend, frontend and supervisor normally. Do not run old workers or standalone inference concurrently.

Extraction POST returns 202 with status; GET on same path returns status. Existing voice ownership and consent checks remain. ASR submit persists source and job state; existing history/detail/edit and Developer API remain compatible. The worker consumes local jobs in modification-time order ahead of TTS, unloads its TTS model, and runs ASR/extraction in disposable subprocesses. ASR timeout 2 hours, extraction 15 minutes. Queued jobs survive restart; interrupted jobs fail, not automatically replayed. Re-submit failed ASR; retry failed extraction on existing voice. Legacy queued ASR records lack source metadata and fail explicitly. Benchmarks still require stopped supervisor.

Limits: single worker, local filesystem, no distributed scheduling, no cancellation of extraction/ASR, no exact percentage, no global queue limit, ASR per-owner cap is best effort, local jobs can starve TTS under sustained load. Child lock reduces orphan overlap but does not guarantee process-tree termination after abrupt parent death (including a small child startup race). Interrupted uploads may remain; no automatic orphan cleanup. Native unload is best effort; memory admission is heuristic. ASR now reloads models per job. Browser polling resumes readiness refresh after navigation but active progress/error is only shown during an extraction action. No Windows/DB/browser inference test performed here. Back up local edits, especially API files; transcription/diarization service files are not replaced.
