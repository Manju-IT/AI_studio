# Phase 10 — local worker hardening
Stop all old workers before replacing files. Back up the replaced files. No migration or new dependencies. Run from root: `python scripts/run_inference_supervisor.py` instead of `python inference/worker.py`. Do not launch the legacy inference/manager/worker.py. Start API and UI as usual.

The worker holds a local OS file lock for its lifetime. Recovery also acquires that lock; the worker uses forced recovery only while owning it. Interrupted jobs are failed (or cancelled if requested), never automatically replayed. Retry manually. Supervisor restarts abnormal exits with backoff and stops after five failures within successive short-lived runs; duplicate-worker exit 73 is not restarted. A generation timeout always exits the worker, regardless of the old restart-on-timeout setting. Idle unloading is checked between jobs, with default 60 seconds. Qwen cold load requires 9 GiB available and a configured inference budget of at least 8800 MiB (default 9000). This is a heuristic, not a memory guarantee. Heartbeat is refreshed every two seconds when the event loop can run. Job detail, chunks, retry and SSE are owner scoped; recovery endpoint is admin-only. Existing model adapters and ASR files unchanged.

Test: `python backend/tests/test_worker_lock.py`. Start supervisor, try starting a second worker (must exit 73), generate Piper audio, verify completion timestamp, then Qwen if RAM permits. During a disposable generation, terminate only the worker child using Task Manager; supervisor should restart it and mark interrupted job failed. Verify queued jobs continue. Verify another account cannot read or retry the job. Do not deliberately trigger a native crash. Stop supervisor with Ctrl+C. Stop worker before dashboard model benchmarking; benchmarking still executes in API process. Avoid simultaneous ASR/diarization and Qwen; no cross-service resource lock yet. No full database or Windows runtime tests were performed. A crash between asset persistence and job completion can leave an orphan asset. ASR remains non-durable. No changes to frontend, webhooks or rate limits.
